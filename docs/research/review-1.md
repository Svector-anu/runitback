# Adversarial review 1: existing editor, before the agent layer

Scope: read-only review of `src/engine/**`, `src/app/**`, `src/platform/**`, `src/render/**`, `src/export/**`, `src/ui/**` at git HEAD `e1007c4` (other agents' uncommitted files in `src/engine/agent`, `src/engine/analysis`, `src/platform/agent-bridge*`, `src/app/agent-bridge-wiring.ts`, `src/ui/agent`, `tools/mcp` were ignored; the three tracked files they modified, `commands/history.ts`, `commands/timeline.ts`, `editor/editor.ts`, were verified to be additive, and all line numbers below match HEAD).

Method: read the code, then proved what could be proved with scripts in `docs/research/repros/` (all uncommitted, none in `tests/`). Run with `pnpm exec tsx <file>`:

| Repro | What it covers | Result |

Claims that do not hold as stated: "undo restores exact snapshot" (it also rewinds the asset list, P0-1); "project switch awaits closeProject" (it does not serialize open/close, P1-2); "save manager serialises saves and re-queues edits made mid-save" (true for autosave, false for `flush()`, P0-4); "StrictMode double-mount is exercised by every e2e run" (it is, but passes because the race is benign in the happy path, P1-2); "per-asset decoder access is serialised" (true) but "Derived resources cleaned up" is false for the audio-engine commit listener (P1-3).

## P0: data loss, corruption, crash, wrong output

### P0-1 Undo/redo rewinds the asset list; the orphan sweep then deletes the media bytes
- Where: `engine/commands/types.ts:6-11` (`assets` is part of `EditorDocument`), `engine/commands/history.ts:73-91` (undo/redo return `entry.before/after` wholesale), `engine/editor/editor.ts:226-228` (`registerAsset` commits outside history), `editor.ts:152` (`assetIds` derived from `doc.assets`), `app/services.ts:127` + `engine/persistence/projects.ts:88-93` (`collectOrphans`).
- Wrong: asset registration is not undoable but the asset list is inside every undo snapshot. Undoing to a snapshot taken before the import removes the asset from `doc.assets`; redo restores the old list (also drops assets registered in between).
- Scenario: (1) move a clip (history entry E0, `before.assets=[]`); (2) import `b-roll.mp4`; (3) add it to the timeline; (4) Ctrl+Z three times. After step 4 `doc.assets=[]`, the Assets panel is empty, autosave persists `assetIds: []`, and on Exit `collectOrphans` calls `assets.remove()` for `b-roll.mp4`: the file is permanently deleted. Redo cannot bring it back.
- Repro: `engine-invariants.ts` E7 (`assets after 2 undos=` empty, `toProject.assetIds=[]`) and E7b (redo drops an asset registered after an undo). Reproduced, confidence high. Browser run unverified, but the path is pure engine + two function calls.
- Minimal fix: never let history restore assets. In `CommandManager.undo/redo` (or `Editor.commit` for history snapshots) return `{...snapshotDoc, assets: unionById(current.assets, snapshotDoc.assets)}`; make removal an explicit set carried by `removeAssetsCommand` (e.g. `doc.removedAssetIds`) so redo can re-remove. Independently, make `collectOrphans` only delete assets that no scene references AND are not in the in-memory registry.
- Test: engine test: register asset after an edit, undo twice, assert `getState().doc.assets` still contains it and `toProject().assetIds` lists it; redo after a registerAsset-in-between keeps it.

### P0-2 Engine commands accept NaN / Infinity / negative / fractional numbers, and a throw during `commit` leaves the editor poisoned
- Where: `engine/timeline/update-pipeline.ts:44-78` (patch values are merged unchecked; `Math.max(0, NaN)` stays NaN), `commands/timeline.ts:85-122` (`insertElement` trusts `element`), `editor/editor.ts:108-116` (`commit` does `set()` first, then `playback.reconcile()`, then listeners), `engine/timeline/tracks.ts:38-44` (`totalDuration` calls `mediaTime()` which throws on non-integers).
- Wrong: `updateElements([{patch:{duration:NaN}}])` writes NaN into the document and notifies React subscribers, then `reconcile()` -> `documentDuration` -> `mediaTime(NaN)` throws. `execute` throws to the caller but the document is already committed; `committedListeners` never run (autosave is not triggered), and every later `editor.duration()`, `toProject()`, and `useEditorState((s)=>totalDuration(...))` (ExportButton.tsx:50) throws. There is no React error boundary (`main.tsx` only has `StrictMode`), so the tree unmounts to a blank page. Undo still works at engine level but the UI cannot reach it.
- Same class: fractional ticks (`splitCommand` with `splitTime=sec(1)+0.5`) throw `RangeError` out of `execute` (E9); negative duration is committed (E3b); duration beyond the source breaks `trimStart + duration*rate + trimEnd == sourceDuration` (E3); zero-duration clips are accepted (E6); `Infinity` start on the main track is silently turned into 0 but off the main track would persist.
- Persistence angle: `JSON.stringify` turns NaN/Infinity into `null`; `validateProject` (P1-14) accepts `null` times, so a poisoned project reloads as zero-length garbage.
- Repro: `engine-invariants.ts` E3, E3b, E3c, E3c2, E3d, E6, E9. Reproduced. Confidence high for the engine; the "blank page" consequence is unverified (needs a browser).
- Minimal fix: (a) a `validateElement`/`assertFinite` gate in `insertElement`, `applyElementUpdate`, `pasteElements`, `splitCommand` (finite, integer, `startTime>=0`, `duration>=1`, `trimStart/End>=0`, `|t| <= MAX_TICKS`); (b) make `Editor.commit` exception-safe: compute derived state (`documentDuration`, reconcile) before `set`, or wrap in try/catch that restores the previous snapshot and rethrows; (c) add an `ErrorBoundary` around the editor that offers "Undo last change".
- Test: `tests/engine-validation.test.ts`: each of NaN, Infinity, -1, 0.5, 1e300 for `startTime`, `duration`, `trimStart`, `splitTime` must leave `editor.getState().doc` unchanged (`toBe` identity) and `execute` must throw a typed error.

### P0-3 Overlap, trim-invariant and duplicate-id invariants are enforced only by the drag/drop planners, not by the command layer; real UI path (caption import) breaks them
- Where: `engine/timeline/placement.ts:106-110` + `82-91` (`explicit` placement returns `existing()` without `canPlaceSpans`), `update-pipeline.ts:44-78` (startTime/duration patches never check neighbours), `placement.ts:54-63` (`enforceMainTrackStart` pins to 0 when `requested <= earliest` without checking that the clip then overlaps the earliest clip), `commands/timeline.ts:25-33,98-101` (`addTrack`/`newTrack` accept caller-supplied `trackId` that may duplicate), `ui/assets/OtherViews.tsx:96-104` (caption import).
- Wrong: invariant 3 ("No overlap on a track... nothing pushes or overwrites neighbours") is false for `insertElement({placement:{mode:'explicit'}})` and `updateElements({patch:{startTime}})`.
- Scenarios (inputs): main has `a` at 0..5s; `insertElement(video b @2s, explicit main)` -> `a` and `b` overlap (E1). `updateElements(b, startTime=3s)` from 10s -> overlap (E2). Main has `a` 0..5s and `b` 20s..50s; patch `b.startTime=0` -> pinned to 0, overlaps `a` for 5s (E4). Inserting an element with an existing id duplicates it; `deleteElements` by that id then deletes both (E5, E5b).
- User-reachable: Captions > Import with an SRT that has two overlapping cues (very common for dual-speaker subtitles or ASS layers). `OtherViews.tsx` inserts every cue onto one new text track via `placement: {mode:'explicit'}`. Result: overlapping clips in one track (C3 reproduced).
- Why it matters for the agent: every agent tool that takes a `trackId` goes through these paths; the fuzz proves the UI planners are sound, so the agent will be the first caller to violate the invariant.
- Repro: `engine-invariants.ts` E1, E2, E4, E5, E5b; `captions-dos.ts` C3. Reproduced. Confidence high.
- Minimal fix: in `existing()` (explicit path) return `null` when `!canPlaceSpans(track, spans)`; in `applyElementUpdate` after computing `next`, run `canPlaceSpans` against the track minus the element and throw/return unchanged on overlap; `enforceMainTrackStart` must not return a start that makes `[start, start+duration)` overlap; reject duplicate ids in `insertElement`/`addTrack`; caption import should use `firstAvailable` placement (new track per overlap lane) instead of `explicit`.
- Test: property test that runs the fuzz (copy `docs/research/repros/fuzz-ui-paths.ts`) plus explicit-API cases; assert `insertElement` explicit overlap throws; SRT with overlapping cues yields two text tracks.

### P0-4 Exiting a project can silently lose the last edits (flush is a no-op while a save is in flight; failures are swallowed; thumbnail failure skips the flush)
- Where: `engine/persistence/save-manager.ts:96-103` (`flush` -> `saveNow` returns immediately when `this.saving`), `save-manager.ts:111-118` (catch swallows and reschedules), `app/services.ts:121-137` (`closeProject`: `updateThumbnail()` runs first inside the same `try` as `flush`; any throw skips `flush` and `collectOrphans`; then `editor.close()` discards the in-memory document).
- Wrong: (1) S1: an autosave write is in flight (100 ms in the repro, realistically 10-300 ms for a multi-MB project JSON that embeds the thumbnail data URL), the user edits once more and presses Exit. `flush()` returns after 0 ms, `closeProject` proceeds, `editor.close()` runs; the re-queued timer then hits `!hasProject` and the edit is lost. (2) S2: with failing storage `flush()` resolves normally (`threw=false`, `saveCount=0`), so the caller proceeds to `collectOrphans(editor.toProject())` and deletes media the *persisted* project still references. (3) `updateThumbnail` renders frame 0 through the decoders; any decode error (corrupt asset, unsupported codec after a browser update) throws before `flush`.
- Scenario: edit, wait 800 ms (autosave starts), edit again, click Exit within the write window: second edit gone, indicator never showed an error.
- Repro: `persistence-races.ts` S1 (second edit persisted? false) and S2. Reproduced. Confidence high for the state machine; likelihood in the browser unverified.
- Minimal fix: `flush()` must await the in-flight save and then loop until `!dirty`, and reject when the final save fails; `closeProject` should `flush` first (thumbnail is best-effort in its own try/catch), abort closing (keep the project open and show an error) if flush fails, and only then sweep orphans.
- Test: save-manager unit test with a slow repo: edit during the save, `await flush()`, assert the repo saw both edits; failing repo makes `flush()` reject.

### P0-5 Two tabs on the same origin clobber each other, and one tab's orphan sweep deletes the other tab's imports
- Where: `platform/repositories.ts:51-53` (`put` the whole project, no version/CAS), no `BroadcastChannel`/Web Locks anywhere (`rg` finds none), `projects.ts:88-93` + `services.ts:127`.
- Wrong: Tab A and Tab B both open project P. Tab A imports `x.mp4` (bytes + metadata written, `assetIds` in A's next autosave). Tab B (still holding the old document) closes the project: `collectOrphans(B.toProject())` lists IDB assets, sees `x.mp4` not in B's `assetIds`, deletes it. Also last-writer-wins on the project row: B's autosave overwrites A's timeline edits. `ProjectsService.delete` from the Projects page while the editor is open in another tab is followed by that tab's autosave resurrecting the project without media.
- Repro: none (needs two browser contexts). Unverified, confidence high from the code.
- Minimal fix: take a Web Lock (`navigator.locks.request('opencut:project:'+id, {ifAvailable:true})`) for the lifetime of an open project; second tab opens read-only or is refused. Make the orphan sweep skip assets newer than the project `updatedAt` (or drop the sweep and delete removed assets at command time + refcount).
- Test: Playwright with two pages on one context, import in one, exit in the other, assert the asset survives and the second tab is blocked.

### P0-6 Export reports success while rendering black frames (missing media is not an error; export is not tied to the project lifecycle)
- Where: `export/exporter.ts:122-132` (never inspects `framePlan.missingMedia`), `engine/render/frame-plan.ts:175-179` (collects `missing`), `platform/frame-sources.ts:51-52` (null frame is skipped), `app/services.ts:76-82` (assets whose bytes are absent are dropped from `doc.assets` on open, but their clips remain), `ui/editor/ExportButton.tsx:53-73` (no abort on unmount; `getBlob: services.runtime.getBlob` is bound to the runtime that `closeProject` disposes).
- Wrong: (a) a project with a clip whose asset bytes are missing (after P0-1, P0-5, quota eviction, manual OPFS clear) exports "Export complete" with black frames and no audio for that clip; (b) leaving the editor mid-export (Exit, browser Back) keeps the export running; `runtime.dispose()` clears the blobs, so the remaining frames silently render black, then a success toast and a corrupt-looking file download.
- Repro: none (needs browser/WebCodecs). Unverified; confidence high from reading.
- Minimal fix: in `exportProject`, fail up front when `buildFramePlan(...).missingMedia` is non-empty for any sampled frame (or pre-scan elements vs `doc.assets` + `getBlob`), and have `getBlob` throw `MissingMediaError`. Abort the export controller in a `useEffect` cleanup of `ExportButton` and in `closeProject`.
- Test: unit test of `exportProject` with a `getBlob` returning undefined must reject; e2e: exit during export shows no download.

## P1: user-visible bugs, races, leaks, perf cliffs

### P1-1 `importFiles` registers into whatever project is open when each file finishes
- `app/services.ts:164-177`: `projectId` is captured at call time, but `this.runtime.setBlob` and `this.editor.registerAsset(info)` act on the *current* runtime/editor. If the user exits and opens project B while a long import runs, bytes are stored under A, the asset appears in B's `doc.assets` and autosaves into B's `assetIds` with no bytes under B (`loadAssets` filters it on next open; its clips show missing media). A also keeps orphan bytes. After `closeProject`, `registerAsset` also commits into the empty placeholder document.
- Fix: capture the runtime/editor generation at start and abort (`if (this.openProjectId !== projectId) throw/skip`) before `registerAsset`; also cancel imports on `closeProject`.
- Test: services-level test with fake repos: start slow import, switch project, assert B untouched.

### P1-2 `openProject`/`closeProject` are not serialized; the last loader wins; StrictMode double mount runs two loads
- `app/services.ts:66-91,121-137`, `ui/editor/EditorPage.tsx:71-88`, `ui/pages/ProjectsPage.tsx:86`. `closeProject()` is a no-op while `openProjectId` is still null (load in flight), so the effect cleanup (`canceled=true; closeProject()`) does nothing; the in-flight load then completes and calls `editor.load`. Navigating A -> B quickly (or Back/Forward) lets A's slower load finish last: the UI shows A while the URL says B, and edits autosave into A. `canceled` only guards `setStatus`; `ready` comes from the store (`meta!==null`). StrictMode runs two concurrent `openProject(id)`, each creating a `MediaRuntime` (first one orphaned) and each calling `startAudio` (P1-3). Concurrent `closeProject()` calls (EditorPage cleanup + ProjectsPage effect) both pass the guard, both run `flush`/`collectOrphans`; the second's `toProject()` can throw after the first closed (swallowed by `console.error`).
- Fix: single-flight queue in `AppServices` (`private chain = Promise.resolve()`; every open/close appended), with a generation token checked after each await in `openProject`; `closeProject` while a load is pending must cancel it.
- Test: unit test with controllable repositories: `open(A)`, `open(B)`, resolve A last; assert `currentProjectId==='B'` and `editor.getState().meta.id==='B'`.

### P1-3 `startAudio` leaks one `editor.onCommitted` listener per open; stale engines recreate AudioContexts
- `app/services.ts:93-108`. The unsubscribe returned by `onCommitted` is discarded; old `AudioEngine`s are `dispose()`d but their listener stays. After the next project open, any commit during playback calls `oldEngine.restart()`; `restart()` after `dispose()` runs `ensureContext()`, creating a new `AudioContext` and an interval timer that is never stopped (`audio-engine.ts:63-75,118-125`). Browsers cap live AudioContexts (Chrome ~6); StrictMode doubles the leak in dev.
- Fix: keep the unsubscribe on `AppServices` and call it in `startAudio`/`closeProject`; guard `restart()` with a `disposed` flag.
- Test: open/close 10 projects, edit during playback, count `AudioContext` constructions (fake `AudioContext` in vitest).

### P1-4 Every view-state write is a "commit": audio restart storm and a full project save per scroll/zoom
- `editor/editor.ts:164-167` (`setViewState` fires `committedListeners`), `160-162` (`updateMetadata` too). `useViewport.ts:54-58` writes `scrollLeft` 300 ms after scrolling, `setZoom` writes `zoomLevel` on every wheel/slider event, `Playhead.tsx:16-22` auto-scrolls during playback. Consequences: (1) `services.ts:105` restarts the AudioEngine on every such event while playing (stop all sources, re-anchor): audible dropouts whenever the playhead auto-scrolls and a restart per wheel notch while zooming during playback; (2) `SaveManager.markDirty` re-serializes and writes the whole project (including a ~50 KB thumbnail data URL) for a scroll, and flips the header to "Unsaved changes"; `updatedAt` is bumped by scrolling.
- Fix: separate `onCommitted` (document) from `onViewChanged`; only document commits restart audio; view-state saves piggyback on the next document save or use a long (5 s) debounce.
- Test: engine test: `setViewState` must not invoke `onCommitted` listeners (or must not restart audio).

### P1-5 AudioEngine: a tick in flight across a seek poisons the cursor map
- `platform/audio-engine.ts:79-106`. `tick()` captures `generation` and `horizon`, then for each clip does `this.cursors.set(clip.key, horizon)` *before* `await this.deps.sinks.get(...)`. If `restart()`/`stop()` runs while the tick is awaiting (seek, play/pause, any commit), `cursors` was cleared and re-used by the new generation; the old tick's later loop iterations write stale `horizon` values into the new map and then `continue` on the generation check. The new tick then computes `from = max(cursor, nowTimeline)` with a cursor ahead of the new playhead and skips scheduling that clip until the playhead catches up (e.g. seek backwards 10 s during playback with two audio clips: silence for those clips).
- Unverified (needs real timing); confidence medium-high from reading. Fix: move the `cursors.set` after the generation check, or key cursors by generation.
- Test: fake sink with controllable promises; call `restart()` between awaits; assert cursors empty afterwards.

### P1-6 Any click outside the Export popover (or Esc) cancels a running export
- `ui/editor/ExportButton.tsx:75-79,87`: `Popover.onClose = close`, and `close` calls `abort.current?.abort()`. `Popover` closes on any `pointerdown` outside (`Popover.tsx:48-53`) and on Escape (even though Esc is also the global "cancel selection" key). A 10-minute export is cancelled by clicking the timeline, with no confirmation and no toast (state silently returns to idle). No progress is visible once the popover is closed.
- Fix: closing the popover must not abort; keep progress in a header chip; only the Cancel button aborts. Confirm on unmount/navigation.
- Test: Playwright: start export, click preview, assert export continues and a download occurs.

### P1-7 Inspector "Content" textarea: preview/commit compare uses the previewed value, so typed text is discarded or the field remounts
- `ui/properties/ParamControl.tsx:78-80`: `defaultValue={String(value)} key={String(value)}`, `onChange` -> `editor.preview(...)`, `onBlur` -> `if (e.target.value !== String(value)) commit else discardPreview()`. `PropertiesPanel` reads tracks through `useTracks()` (the *preview* document), so after the first keystroke `value` already equals the typed text: (a) the `key` changes and React remounts the textarea (focus and caret lost after every character); (b) on blur the equality check is true, so `discardPreview()` runs and the edit is thrown away. The double-click `TextEditOverlay` path commits correctly (`finish(true)`), which is why the e2e (which only edits colour/size) did not catch it.
- Unverified in a browser; confidence high from the code. Fix: compare against the committed value (`editor.getState().doc`), drop the `key`, commit on blur/Enter unconditionally when a preview exists.
- Test: Playwright: select a text clip, type "Hello" in Content, blur, assert preview canvas shows it and undo reverts it.

### P1-8 Global shortcuts swallow Enter and Space on every focused button (keyboard trap)
- `engine/editor/actions.ts:19` binds `goto-start` to `enter` and `toggle-play` to `space`; `app/actions.ts:41-56` handles keydown in the capture phase, skips only `input/textarea/select/contentEditable` (`isTypableTarget`) and calls `e.preventDefault()` for any matched action. With focus on a toolbar button, export button, tab, menu trigger, or clip (`role=button`), Enter/Space triggers a transport action and suppresses the button's own activation. Keyboard-only users cannot operate the editor's buttons (Chrome: `preventDefault` on keydown cancels the click). Dialogs/menus are exempt via `getOverlayDepth()`, which masks the problem in e2e (mouse driven).
- Unverified in a browser for Space (click fires on keyup); Enter high confidence. Fix: ignore bound actions with no modifier when `target.closest('button,[role=button],[role=tab],[role=menuitem],a,summary')` for `enter`/`space`, or drop `enter` as a default binding.
- Test: Playwright: Tab to "Zoom in" button, press Enter, assert zoom changed and playhead did not move.

### P1-9 Scrub/background/preview/split gestures have no `pointercancel` handler; a lost `pointerup` leaves the editor stuck
- `ui/timeline/controllers.ts:244-294` (`startScrub`) and `298-342` (`startBackgroundGesture`) listen for `pointermove`/`pointerup` only, while `startClipDrag`/`startResize` handle cancel. Same in `ui/preview/PreviewOverlay.tsx` `trackWindow` and `ui/primitives/split.tsx:44-52`. If the browser fires `pointercancel` (touch scroll, pen, OS gesture, window blur on some platforms), `playback.setScrubbing(true)` is never reset: `AudioEngine.sync` requires `!isScrubbing`, so audio never plays again until another scrub; the `edgeAutoScroll` rAF loop and window listeners leak and keep scrolling; `interactionStore.mode` stays "scrub" (so `cancel-interaction` Escape is ignored, `actions.ts:53`).
- Unverified (needs touch/pen); confidence high. Fix: shared `trackPointerGesture` helper that registers `pointercancel`, `blur`, `lostpointercapture`, and Escape, always running one `finish()`.
- Test: Playwright with `dispatchEvent('pointercancel')` mid-scrub; assert playback can start and `isScrubbing` is false.

### P1-10 ASS dialogue stripping is quadratic: an 80 KB hostile line freezes the tab for ~9 s
- `engine/captions/parse.ts:169`: `.replace(/\{[^}]*\}/g, "")` on each Dialogue text. A text of N unmatched `{` costs O(N^2). Measured: 20 000 -> 0.42 s, 40 000 -> 1.65 s, 80 000 -> 9.4 s (`captions-dos.ts` C1). Runs on the UI thread in `OtherViews.tsx:93-97`, no size limit on `file.text()`.
- Fix: single-pass state machine (skip from `{` to the next `}` or end), cap file size (e.g. 5 MB) and cue count.
- Test: `parseAss` with 200 000 `{` completes in < 100 ms.

### P1-11 Unbounded timestamps persist a project that cannot be exported or navigated
- `parse.ts:91` (`assTime` hours `\d+`) + `mediaTimeFromSeconds`: `Dialogue: 0,99999999999:00:00.00,...` yields a cue at 4.3e19 ticks (`Number.isSafeInteger` false). `insertElement` accepts it (P0-2), `totalDuration` becomes 4.3e19 ticks (1e11 hours), autosave persists it, `planExport` computes ~1e16 frames and the export loop never terminates; timeline content width is astronomically large (clamped by the browser). SRT is limited to two-digit hours so not affected (C4 is a non-finding).
- Repro: `captions-dos.ts` C2. Reproduced. Fix: global `MAX_TIMELINE_TICKS` (e.g. 24 h) enforced in `insertElement`, `applyElementUpdate`, parser and `mediaTime`; `exportProject` refuses > N frames.
- Test: parser rejects cues beyond the cap and reports them as skipped.

### P1-12 Timeline re-renders every clip on any interaction; no clip virtualization
- `ui/timeline/Timeline.tsx:64` (`interactionStore.use((s) => s)` subscribes to the whole object; every `interactionStore.set` creates a new state), `Timeline.tsx:344-352` (inline `box={{...box, top: box.top}}` and fresh arrow props), so `ClipView`'s `memo` (`ClipView.tsx:197`) never bails out. Triggers: each pointermove during drag/resize (preview doc changes), each `scrollLeft` change (`useViewport` `setScrollLeft` on every scroll event), every selection change. All clips are rendered regardless of the viewport (only the ruler is virtualized); each re-render runs `listKeyframes`, builds Maps, and re-mounts per-clip `Waveform` effects deps checks. With ~2 000 clips (an auto-assembled agent edit) drags and scrolling will drop frames; DOM node count grows linearly.
- Unverified (profile needed); confidence high from reading. Fix: stable `box` object (memoize per track), `useCallback` handlers keyed on ids, select only `mode`/`snapTime` slices, windowed rendering by `[scrollLeft - buffer, scrollLeft + width + buffer]`.
- Test: React Profiler/Playwright trace with 2 000 clips: pointermove drag frame < 16 ms; a render-count test asserting unaffected `ClipView`s do not re-render.

### P1-13 Preview/export memory and CPU cliffs
- Preview renders at full project canvas size (`PreviewPanel.tsx:131`, canvas width/height = project size; `SettingsView.tsx:71-72` allows up to 7680x7680). `Compositor` (`render/compositor.ts:35-41`) allocates three full-size canvases (output, layer, scratch); each layer does `clearRect` over the full canvas and a full-canvas composite (`compositor.ts:94-100,120-127`), so cost is O(layers x W x H) per frame, plus a second full-canvas copy per blur (`:102-118`) and for scene effects.
- Video decode is full resolution regardless of canvas: `platform/video-frames.ts:55,58` uses `CanvasSink` without width/height (probe uses sized sinks, `probe.ts:76`); a 4K clip decodes 33 MB frames each time, and `CachedFrameSources` keeps the previous map alive until the next prepare.
- Export: `exporter.ts:89-91,136-141` buffers the whole file in a `BufferTarget` and then copies it into a `Blob` (2x peak); `export/audio-mix.ts:15-29` schedules every buffer of every clip on one `OfflineAudioContext` before `startRendering()` (all decoded PCM resident: an hour of stereo float is ~1.2 GB) and the audio is added in one `audioSource.add(mixed)` before the first video frame (muxer interleave buffering unverified). The audit acknowledges only the 210 MB mix figure.
- Unbounded: `CommandManager` history has no cap (see P1-18).
- Unverified (no heap profile run). Fix: decouple preview resolution (render at <= 1280 px and scale), pass `{width,height,fit}` to `CanvasSink`, dirty-rect or skip empty layers, stream export to OPFS via `StreamTarget`, chunk audio mixing in 30 s windows.
- Test: perf smoke in Playwright (4K project, 10 overlays, 3 s of playback; assert dropped-frame ratio and `performance.memory` ceiling).

### P1-14 Project validation is skeleton-only; one bad row hides or blocks a project
- `engine/persistence/serialization.ts:44-63` validates only that `scenes[].tracks.{main,overlay,audio}` are records/arrays; it never checks `elements` is an array (S3b: `track.elements is not iterable` later, blank page), element field types (S3: `startTime:null, duration:null` passes and flows into arithmetic as 0), duplicate ids, or `currentSceneId`/ref consistency. `IdbProjectRepository.list` (`repositories.ts:33-44`) silently skips unreadable rows, so a project that fails validation vanishes from the list and cannot be deleted (storage leak); `openProject` (`services.ts:76-82`) calls `getFile` for each asset sequentially and one throw (transient OPFS error) aborts the open with a generic error. `list()` also fully deserializes every project, including its thumbnail data URL, on every Projects-page visit.
- Repro: `persistence-races.ts` S3, S3b. Reproduced.
- Fix: schema-validate elements (zod-style hand validator) in `validateProject` with a repair/quarantine path ("recover project": drop bad elements, keep original JSON under a backup key), show unreadable projects with a delete button, store `metadata` in a separate IDB index so `list()` does not parse bodies.
- Test: fuzz `deserializeProject` with mutated JSON of a valid project; expect either a valid project or `ProjectFormatError`, never a project that throws in `Editor.load`/`duration()`.

### P1-15 Param/effect/mask/settings values bypass `coerceParam`; some values stall the compositor
- `engine/model/definitions.ts:14-31` has `coerceParam` (and it lets `Infinity` through: `Number.isNaN` instead of `isFinite`), but no command uses it: `setElementParams`, `updateElements`, `updateClipEffectParams` (`commands/properties.ts:164`), `updateMaskParams`, `updateSettings` (`commands/project.ts:6-11`: any canvas size/fps) take raw values. The UI clamps in `NumberField` only. Examples: blur `intensity: 1e9` -> `ctx.filter = blur(2e8px)` (`compositor.ts:105-114`) can hang the GPU process; `canvasSize 100000x100000` allocates three giant canvases and throws `RangeError` per frame; `fontSize: 1e9` / content of 1 000 000 lines costs a `measureText` per line per frame (`render/text.ts:49-51`); `fps: 1000` from `frameRateFromFloat` (also adopted automatically from a probed file, `commands/timeline.ts:70-83`, `probe.ts:85`) multiplies export frames; `frameDuration` of 0 for fps > 120000 makes `planExport.frameCount` Infinity (`frame-rate.ts:41-43`, `export/plan.ts:26-27`). Render-time reads use `numberParam` (finite-safe), so NaN params are survivable, but huge finite ones are not.
- Fix: one `normalizeParams(defs, values)` in the command layer driven by the same defs as the inspector, and bounds on `canvasSize` (<= 8192 and area <= 33 M px) and `fps` (1..240).
- Test: command-level tests with out-of-range values assert clamping/rejection; compositor smoke with blur 1e9.

### P1-16 `loadFont` is a third-party network request driven by document data
- `platform/fonts.ts:12-30`, called from `ui/properties/ParamControl.tsx:84` (any typed family), `app/services.ts:110-118` (every text element's `fontFamily` on project open), and caption styles from ASS `Fontname`. The family string is placed in `https://fonts.googleapis.com/css2?family=...` (properly encoded, no injection), so any imported project/ASS file/agent edit can make the editor send an arbitrary string (and the user's IP) to Google. For a "local-first, private" product and for a prompt-injected agent that is a data-exfiltration channel (family names can carry data in the query string). Failure is cached forever in `loaded` (`:28`), so a transient offline start never retries. `render/text.ts:45` interpolates the family into `ctx.font` inside quotes; a family containing `"` makes the font shorthand invalid and the canvas silently keeps the previous font (wrong output, no error).
- Fix: allowlist of known Google families (bundled list in `ui/properties/fonts.ts`), self-host or bundle, escape/validate family names (`/^[\w \-]{1,64}$/`), do not cache failures.
- Test: `loadFont('x"; evil')` must not create a `<link>`; family with `"` renders with fallback font.

### P1-17 `ProjectsService.duplicate`/`delete` are not atomic
- `engine/persistence/projects.ts:57-79`: `duplicate` saves the new project row *before* `copyAll` of media (S5: a failed copy leaves a listed project with no media; repro `persistence-races.ts` S5). `delete` removes bytes first, then the project row: failure in between leaves a project row whose media is gone. Neither handles quota errors mid-copy (OPFS copy of many GB).
- Fix: copy media first under the new id, then write the project row; on failure remove the partial copy. For delete, remove the row first, then the bytes (an orphan sweep can reclaim bytes).
- Test: failing `copyAll` leaves `list()` unchanged.

### P1-18 History is unbounded and a stale drag plan throws from the pointer handler
- `CommandManager.history` (`history.ts:21-22,60-62`) never trims; each entry holds `before` and `after` documents (structural sharing helps, but every edit to a large track copies its element array, so N edits on an M-element track retain O(N x M)). An agent issuing thousands of edits will balloon memory; `Editor.undo` through 5 000 steps is also user-hostile. Add a cap (e.g. 200 entries) or coalesce agent bursts (the uncommitted transaction work covers grouping, not size).
- `Editor.preview` (`editor.ts:194-198`) evaluates a command built from state captured at gesture start. If the document changes mid-gesture (Delete key, Ctrl+Z, agent edit; shortcuts are not suspended during drags), the next pointermove calls `applyGroupMove` for a missing element and throws "Cannot move missing element" inside the window listener on every move event (E10 reproduced). `commit()` already cleared `previewCommand`, so state is consistent but noisy; with an agent editing concurrently this becomes the normal case.
- Fix: cap history; in drag controllers re-validate members against `getState().doc` each move (or catch and `cancel()`); suspend shortcuts while `interactionStore.mode !== 'idle'`.
- Test: engine test that a stale plan is rejected without throwing out of `preview`.

## P2: maintainability, accessibility, polish

- **P2-1 Hard-coded schema version**: `editor.ts:154` writes `version: 1` instead of `PROJECT_SCHEMA_VERSION`; the first schema bump would write stale versions (S4).
- **P2-2 Popover has no focus management**: `ui/primitives/Popover.tsx` portals to the end of `<body>`, never moves focus in, never restores it (DropdownMenu restores manually; Export popover does not), has `role="dialog"` but is not modal and has no Tab trap, so keyboard users Tab out of the export dialog into the page behind it. Menus lack Home/End/typeahead (`Menu.tsx:22-29`).
- **P2-3 Mis-specified ARIA**: `Ruler.tsx:11` is a `role="slider"` with constant `aria-valuenow={0}` and no `tabIndex`; `Playhead.tsx:26-31` is a `<button role="slider">` without `aria-valuemax`; clips are `role="button"` with `aria-pressed` and no keyboard way to move/trim/split-by-position (Enter/Space only select, and see P1-8); toasts auto-dismiss after 4 s/8 s (`toast.tsx:21`), too short for screen-reader users; `Timeline` regions lack `aria-live` for edit results.
- **P2-4 Listener leaks**: `EditorPage.tsx:96` adds a `visibilitychange` listener that is never removed (one per mount; StrictMode doubles it); `MediaView.tsx` re-registers a `paste` listener every render (effect has no deps) and imports pasted files from any focused field.
- **P2-5 `beforeunload` guard misses the in-flight save**: `EditorPage.tsx:91-93` checks `isDirty`, which is `false` during a save (`save-manager.ts:105`), so closing the tab mid-write shows no warning; `visibilitychange` flush is async and unawaited (fine on desktop, best-effort only).
- **P2-6 Frame plan rebuilds sorted lists every frame**: `engine/render/frame-plan.ts:88-93` filters and sorts every track on every preview/export frame (O(total elements log n) per frame); with 5 000 elements an export spends most time here. Precompute per-track sorted arrays per document identity.
- **P2-7 `removeAssets` leaves derived caches**: `services.ts:191-194` releases only the video decoder; audio sinks, images, waveforms and object URLs of removed assets stay until project close (`MediaRuntime.release` exists but is unused there).
- **P2-8 Waveform quality/cost**: `Waveform.tsx:6,17-18` caps the canvas at 2048 px and stretches it (blocky at high zoom, bucket resolution 100/s vs 5 000 px/s at zoom 100); `platform/waveform.ts:54-62` decodes the whole file on first draw with no cancellation or progress, and failure is cached as `null` forever (`:45-49`).
- **P2-9 `VideoSource` can re-open after dispose**: `platform/video-frames.ts:63-71,92-96` and `MediaRuntime.dispose` (`media-runtime.ts:48-54`): a `getFrame` that starts between `sources.clear()` and `blobs.clear()` creates a new `VideoSource` that is never disposed (leaked `Input`/decoder). Narrow window; unverified.
- **P2-10 Non-divisor frame rates**: `export/plan.ts:26` divides by the rounded `frameDuration` (e.g. 47.952 fps -> 2503 vs 2502.5 ticks), so frame counts can differ by one from `frameStartTime`-based playback at long durations.
- **P2-11 Future-proofing**: `ClipView.tsx:103` builds `url(${asset.thumbnail})` unescaped; safe today (thumbnails are locally generated data URLs) but an agent/importer that sets `thumbnail` to an arbitrary string can inject CSS. `exportFileName` (`export/plan.ts:36-39`) does not strip control characters, trailing dots or reserved device names.
- **P2-12 Lingering previews**: gesture controllers rely on matching `commitPreview`/`discardPreview`. `ColorField` (`fields.tsx:122`) previews on `input` and commits on `change`; if the component unmounts between them (selection change while the picker is open) the preview document stays active (`effectiveDoc`) and diverges from what autosave and export use (they read `doc`). Unverified.
- **P2-13 Caption import cost**: `OtherViews.tsx:96-104` does one `insertElement` per cue (each copies the track array, O(n^2)) and measures text synchronously; a 20 000-cue SRT freezes the UI for seconds. Build the track in one command.
- **P2-14 Docs drift**: `CLAUDE.md` invariant 4 ("Every document change is a Command ... Undo restores a whole-document snapshot") and invariant 3 are true only for UI-reachable calls; document the command-layer preconditions once P0-2/P0-3 land.

## Agent-bridge hazards (area f), derived from the above

The bridge code is new and out of scope, but these existing behaviours decide how dangerous it is:
1. **Commands are the trust boundary and they currently have no validation** (P0-2, P0-3, P1-15, P1-11). A WebSocket client that can send `updateElements`-shaped payloads can poison the editor (blank page), corrupt invariants, persist an unexportable project, or allocate GBs by setting canvas size/blur.
2. **`execute` throws after committing** (P0-2): bridge code that catches and reports "failed" will leave a half-applied state; use the new transaction rollback for every agent call and make `commit` exception-safe.
3. **Exfiltration and egress**: `loadFont` makes third-party requests with attacker-chosen strings (P1-16); exported blobs are saved via `<a download>` (`ExportButton.tsx:32-41`, `app/agent-bridge-wiring.ts:209` does the same): ensure the bridge cannot trigger downloads or file reads without a user gesture.
4. **Browser-to-loopback**: any web page can open `ws://127.0.0.1:<port>` (WebSocket is not subject to CORS or Private Network Access preflight). The server must check `Origin` against an allowlist, require a per-session random token passed out of band, bind to 127.0.0.1 only (not `localhost`/0.0.0.0), and reject non-JSON/oversized frames. DNS rebinding makes a Host-header check necessary too. Unverified: I did not read the new bridge.
5. **Multi-tab** (P0-5): two editor tabs both connect to the bridge; the agent edits whichever answers, then the other tab's autosave clobbers it.
6. **Concurrency with the user** (P1-18): agent edits during a user drag throw in pointermove; history grows without bound.
7. **Project switch** (P1-1, P1-2): an agent session spanning an open/close can register assets into the wrong project; tie every agent session to a project-open generation id.
